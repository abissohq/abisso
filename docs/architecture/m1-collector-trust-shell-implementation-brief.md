# M1 — Collector Trust Shell implementation brief

**Status:** implementation brief; M1 is not complete.

**Authority:** the six frozen product and architecture specifications, in their documented order, then ADRs 0001–0006, `CONTEXT.md`, the M0 Heartbeat brief, and the current implementation. This brief implements those decisions; it does not revise the frozen specifications.

**Milestone exit evidence:** Apple Silicon macOS install and authentication; consent; pause with queue inspect/discard; private-next-session exclusion before the shared outbound queue; exclusions; preview; redaction; encrypted offline buffer; and a signed development update path.

## Problem Statement

M0 proves a synthetic canonical event can pass authenticated ingestion, durable acceptance, asynchronous projection, realtime invalidation, and minimal Live. A person cannot yet install an Abisso collector on a clean Mac, authorize that machine, control what leaves it, or rely on an encrypted offline queue. The existing browser login binds a synthetic M0 user, and the current canonical source contract accepts only `synthetic_m0`. M1 must make the local trust boundary real without claiming real Claude Code or Codex observation.

## Solution

Ship a per-user Apple Silicon macOS collector and CLI with Abisso-owned enrollment, explicit consent, local privacy controls, a deterministic post-policy event representation, and an encrypted bounded queue. Exercise the whole path using a visibly synthetic, user-invoked M1 fixture source. Reuse M0's ingestion, immutable event identity, request replay, source checkpoints, worker, projection, SSE, and Live behavior. Add the minimum browser, machine, policy, source-profile, and local-runtime contracts needed to connect that path. The safe failure mode is lost visibility with an honest collection gap, never expanded collection.

## User Stories

1. As a developer, I want to inspect what Abisso observes and excludes before installing, so that I can decide whether to use the collector.
2. As a developer, I want to install a signed collector without granting it root, Full Disk Access, or accessibility access, so that its local authority stays narrow.
3. As a developer, I want to sign in through Clerk and explicitly create or join my single workspace, so that machine enrollment uses the workspace I chose.
4. As a developer, I want to confirm a bounded machine display name and collector scope in my browser, so that I recognize the device I authorize.
5. As a developer, I want to review a local dry-run preview and consent to a specific policy version, so that collection does not begin silently.
6. As a developer, I want to pause observation and transmission locally, so that an offline server cannot override my choice.
7. As a developer, I want to inspect queue counts and discard approved buffered records while paused, so that I control pending transmission.
8. As a developer, I want to preview the exact approved records that would leave my device, so that the preview reflects the upload rather than a sample transformation.
9. As a developer, I want to arm my next fixture session as private, so that none of its facts enter the shared outbound queue.
10. As a developer, I want a running fixture session to remain private after I switch it, including across restarts, so that later activity is not shared accidentally.
11. As a developer, I want repository and path exclusions to apply before identifiers are derived, so that excluded information leaves no repository or path-derived trace.
12. As a developer, I want approved events to survive an outage encrypted and in order, so that an ordinary connection interruption does not lose them.
13. As a developer, I want clear content-free gap and degraded states after discard, overflow, corruption, or revocation, so that missing evidence is never presented as inactivity or failure.
14. As a developer, I want sign-out to stop collection and destroy workspace-bound local secrets and records while leaving Abisso installed, so that I can enroll again later.
15. As a developer, I want uninstall to remove the installed collector and its local runtime after sign-out, so that Abisso no longer runs on my machine.
16. As a workspace member, I want my enrolled machine to have only write and self-service authority, so that its credential cannot read workspace data or act as my browser session.
17. As an operator, I want signed updates and safe diagnostic codes, so that the collector can be maintained without exposing customer content.

## Implementation Decisions

### Frozen constraints carried into M1

- Run one unprivileged per-user TypeScript collector on Apple Silicon macOS. Intel is optional only if cheap to maintain; Linux follows demand; Windows remains deferred. Native helpers require measured limitations. Keep the backend PostgreSQL-first and modular-monolith-first.
- Local enforcement runs before the shared outbound queue: supported source/version and repository eligibility, repository/path exclusions, pause/private gate, field allowlist, normalization and workspace-keyed derivation, secret/unsafe-value redaction, limits, final prohibited-data assertion, then encrypted queue insertion. Unknown or unsafe material fails closed. Prohibited/P0 content is dropped locally before the shared outbound queue and is never retained, logged, transmitted, exported, emailed, or backed up.
- The browser and collector are separate principals. An authenticated machine can ingest and perform its own lifecycle operations; it cannot read, export, administer, or impersonate a browser user. Workspace scope comes from server authority, not client claims.
- Accepted canonical events remain immutable. Event identity, exact request replay, durable per-event dispositions, asynchronous projection, and the minimal Live path retain their M0 semantics. M1 does not expand M0 replay or correlation.
- Store the local shared outbound queue in bounded SQLite with AES-256-GCM record encryption, unique 96-bit nonces, authenticated machine/schema metadata, and a random device buffer key in non-synchronizing macOS Keychain. Workspace derivation keys are random per workspace and provisioned to authorized machines.

The following browser, collector, queue, fixture, and release choices are accepted M1 implementation decisions from the completed design interview. The later discretion and out-of-scope sections identify choices still left to implementation or another milestone.

### Browser identity and collector enrollment

- Clerk is the managed browser identity provider behind an Abisso browser-auth adapter. Persist a unique internal-user-to-provider-subject mapping. Clerk Organizations do not define Abisso workspaces and Clerk does not authenticate machines. Keep synthetic browser login available only in explicit development/test flows.
- Browser sign-in does not silently create a workspace. The person explicitly creates one or accepts an invitation. Enrollment requires exactly one active V0 workspace membership. The M1 clean-machine path needs workspace creation; full team invitation administration is deferred. Browser sessions use secure HTTP-only cookies, CSRF protection, and server-side membership/role checks.
- The collector generates an ephemeral PKCE verifier/challenge and at least 128-bit state, binds a user-scoped listener to `127.0.0.1` on an ephemeral port, and opens the HTTPS enrollment page. The browser shows the single workspace, user-provided bounded machine display name, and requested collector scope. It issues an Abisso one-use code, expiring within five minutes, bound to user, workspace, enrollment purpose, exact redirect URI, and PKCE challenge. Store only the code digest. The loopback callback carries only code and state. Failure to bind or validate the callback fails closed; no manual credential-copy fallback exists.
- The collector redeems the code over TLS with the verifier. Abisso creates the machine UUID and an installation-bound registration, then returns a rotating refresh credential and audience-restricted access token directly to the collector. Credentials never appear in browser URLs, pages, analytics, logs, shell history, config, environment, or LaunchAgent properties. User-facing machine names never derive from hostname, OS account, MAC address, or serial number.
- Access tokens last at most 15 minutes. Refresh credentials have at least 256 bits of cryptographic randomness or equivalent cryptographic unpredictability, rotate on use, expire after 90 days unused, and are stored as keyed hashes on the server and as non-synchronizing Keychain secrets on the device. Owner/user removal, sign-out, workspace deletion, compromise, or token-family reuse revokes machine authority. One active registration is permitted per installation ID. Reinstall creates a new machine unless a valid retained Keychain item proves continuity and the user confirms reuse.
- Per [ADR 0004](../adr/0004-idempotent-machine-refresh-rotation.md), exact refresh retry is idempotent for 30 seconds from successful rotation only for the same installation, generation, request ID, and request digest. A domain-separated, versioned cryptographic PRF/KDF produces the same 256-bit cryptographically pseudorandom successor from server secret material and the bound predecessor/request context; an ordinary hash digest is not the credential. Store only keyed credential hashes. Different or late reuse revokes the family. A copied identical bearer request is indistinguishable in that window; sender-constrained credentials are deferred until threat evidence or design-partner requirements warrant them.
- Provision the current versioned workspace HMAC derivation key through authenticated machine self-service and keep it in non-synchronizing Keychain. Use type-separated, versioned canonical inputs. Test determinism within one workspace and unrelated refs across workspaces. Missing/stale key blocks affected derivations, never causes an unsalted/global-hash fallback, and does not block repository-free fixture lifecycle. Preserve dual-read/single-write key rotation.

### Consent, local policy, and privacy controls

- Before the first outbound queue entry, show the effective policy version, permitted categories and purposes, prohibited defaults, repository-selection state, pause/private/exclusion controls, retention summary, and a clearly labeled local dry-run preview. Dry run neither queues nor transmits. Record explicit consent per person and machine; decline leaves collection inactive. The workspace cannot remotely activate or broaden local collection.
- Effective collection policy combines server limits, local consent, and stricter local privacy controls. Each queued record retains its policy/schema context. On known narrowing, stop affected observation/upload immediately, recheck existing post-policy bytes, retain unchanged records still allowed, and securely discard the rest with a content-free gap. Broadening leaves old consent in force until fresh local consent enables new categories. Unknown compatibility fails closed. Per [ADR 0005](../adr/0005-server-verified-collection-policy-compatibility.md), ingestion accepts an older narrower-or-equal version only through an explicit server-verifiable relation, never version-number ordering. Revoked or defective versions fail closed with a safe reason. Neither side rewrites queued event bytes or policy versions.
- Pause establishes an atomic local observation/upload-dispatch barrier before success. It stops new observation and transmission. It waits for a known pre-barrier upload result or cancels transport; uncertain approved records stay encrypted and retry only after resume. Cancellation does not imply server cancellation. Already-approved buffered records remain available to inspect, preview, or discard. A server-side pause mirror adds admission defense: `machine_paused` is checked before any durable event disposition. Offline pause works locally; resumed queue drain waits for a server self-service resume acknowledgement.
- `private-next-session` is armed locally and survives restart until consumed or cancelled. The explicit fixture session consumes it before first observation. No shared event, session shell, repository/file ref, usage, outcome, queue row, diagnostic payload, or crash content is created for that session. Switching a running session to private establishes the same barrier for that session, securely discards its unsent queued payloads, and never retransmits that session after the barrier. Private state remains sticky across restarts until that session ends; starting a new non-private session is required to resume shared observation. Persist only minimal opaque local control state, never private payload. Pre-barrier requests may already have been accepted remotely and are not retroactively erased by entering private mode; deletion is separate. Shared state may reveal only permitted gap existence/time bounds, never private identity, provider, repository, activity, cost, or outcome.
- M1 local status displays content-free pause, private, discard, overflow, and corruption gaps. Do not add a canonical gap event or enable `collection.state_changed` merely for M1. The server pause mirror is required; remote queue/gap health and Workstream timeline projection await a later versioned contract.
- Repository selection begins empty. The fixture may use an explicitly user-approved local test repository/worktree to test eligibility, exclusion, canonicalization, and derivation, but must not upload its real repository identity/name/path or represent it as a server-selected GitHub repository. Uploaded M1 tracer evidence remains repository-free. Local rules use repository-root exclusions and repository-relative globs with deny-over-allow precedence. Version canonicalization; normalize separators, dot segments, and Unicode consistently while honoring actual filesystem case sensitivity. Reject traversal and malformed patterns, fail closed on uncertain containment or symlink escape, and treat nested repositories as separate eligibility boundaries. Exclude before deriving identifiers or queueing.
- Only allowlisted canonical fields survive. Drop unknown fields; if a required semantic field is unsafe or missing, drop/quarantine the whole candidate locally without retaining its unsafe value. Apply secret-pattern, entropy, length, and prohibited-content checks to otherwise permitted metadata. Never retain raw input to regenerate an event. One deterministic post-policy serialization is the sole canonical event representation for encrypted queue storage, explicit preview, and upload. A policy recheck retains those exact bytes or discards them. Preview shows decrypted queued bytes and separate safe redaction/drop reason metadata; `queue inspect` shows counts, age, bytes, gaps, and state only.

### Encrypted queue, retry, and authorization loss

- Atomically insert encrypted canonical bytes, nonce/tag, authenticated metadata, source order, policy/schema context, and retry bookkeeping in one SQLite transaction. Only minimal content-free operational indexes may remain outside ciphertext. Validate each record's authentication tag before preview or upload. Missing/denied Keychain buffer key causes Error, stops upload and new observation needing persistence, and never creates a replacement key over an existing queue. The user may restore access or explicitly reset/discard.
- A checked-in versioned M1 fixture load profile and versioned count/byte limits must demonstrate 30 simulated minutes of ordinary M1 fixture interruption. This validates M1 mechanics, not real-adapter volume. On either bound, evict the minimum oldest eligible approved records, preserve retained per-source order, and record a content-free gap. Protect unresolved in-flight requests from eviction; if all records are protected, stop admission and show a capacity/degraded state rather than exceed the bound. No priority classes are invented for M1.
- `accepted`, `duplicate`, deterministic `rejected`, and deterministic `quarantined` are terminal durable per-event outcomes. Retry transport/transient uncertainty with identical request ID, `issued_at`, body, event IDs, bytes, and sequences. M0 request replay is checked before wrapper age. An expired wrapper response must establish no committed replay record for that ID; only then may the collector issue a new wrapper around byte-for-byte unchanged canonical events. Event-level idempotency resolves residual ambiguity. Checkpoints advance only through durable contiguous dispositions. Use per-event outcomes, not a stalled checkpoint alone, to retire individually settled queue records.
- Per [ADR 0006](../adr/0006-local-loss-seals-source-stream.md), overflow, explicit discard, private transition, or authenticated-record corruption seals the affected source stream for new observations. Surviving queued events retain IDs, bytes, source, stream, and sequence and may drain; the old contiguous checkpoint may stay behind a missing range. No local removal fabricates a server disposition or renumbers events. Start a new stream/sequence domain and record only a content-free local collection gap. Persist the last active capability snapshot known durably accepted for each source across restart/update. The new stream may reference it only if still applicable. If none is known—including when loss removes an unaccepted declaration—emit a fresh `capabilities.declared` in the new stream, send it independently, and wait for durable acceptance before creating dependent session evidence. Resolve uncertain older declaration requests before replacing active capability state. A declaration earlier in the same batch never activates a dependent sibling.
- AES-GCM authentication failure never yields partial plaintext, preview, repair, or transmission. Isolate/discard the ciphertext, mark an integrity gap with safe diagnostics, and continue only with independently authenticated later records. A corrupt sequence follows the stream-sealing rule.
- Short access-token expiry or temporary outage retains the eligible queue for refresh/retry. Terminal refresh expiry, confirmed revocation, membership removal, workspace deletion, or family revocation permanently stops upload under that machine; records cannot be transferred, rebound, or re-signed through a new enrollment. The local user may inspect safe counts/state and discard, but may not preview records after workspace authorization is lost. Re-enrollment creates a new machine and queue boundary.
- **Sign-out:** immediately stop collection; request server-side machine revocation when reachable; delete the refresh credential, workspace derivation key, buffer key, encrypted queue, previews, and workspace-bound collector state. Report remote revocation as confirmed only if acknowledged; when offline or unconfirmed, direct the user to web machine removal. Keep Abisso installed; its LaunchAgent/collector installation may remain inactive and unenrolled for later enrollment.
- **Uninstall:** perform sign-out and local-secret destruction, then unload/remove the LaunchAgent, CLI/binary, IPC socket/runtime directory, and installation artifacts. Neither sign-out nor uninstall waits for connectivity before local deletion.

### Fixture, process, diagnostics, and release

- Register one versioned `local_collector` source bound to the enrolled machine with adapter identity `m1_fixture_v1`. Its complete capability snapshot marks only `session.lifecycle`, `session.activity_structured`, and `source.sequence` `available`/`direct`; every other V0 capability is `not_collected`/`none`. A user-invoked fixture start/activity/end uses only canonical kinds already supported by the M0 deployed profile and visibly labels all resulting evidence synthetic. It never impersonates Claude Code or Codex, and there is no fixture bypass of policy, preview, queue, authentication, or ingestion. Acceptance requires an explicitly fixture-enabled development/test backend profile; production rejects it regardless of client claims. Production builds omit/disable fixture invocation. Signed development builds target the development channel; signing itself grants no fixture authority. Legacy `synthetic_m0` remains confined to its development/test path.
- Package a pinned Node runtime, collector daemon, per-user LaunchAgent, and `abisso` CLI. The CLI speaks a small versioned protocol over one user-owned Unix-domain socket in a `0700` state/runtime directory with `0600` socket permissions, verified ownership, and a single-daemon lock. Verify peer UID where reliably available without privileged/native infrastructure; otherwise document filesystem ownership/mode as the M1 boundary. IPC never carries credentials or keys. CLI controls include status, consent, pause/resume, private arm/cancel, fixture session controls, exclusion management, queue inspect/discard, preview, sign-out, uninstall, and update.
- Local structured logs rotate by size/age and use enumerated state/error codes, versions, OS major version, coarse timing, counts, queue age/bytes, and bounded retry/update status. Exclude repository names, branches, paths, derived refs, session/provider IDs, payloads, prompts, terminal content, email, hostname, secrets, and credentials. Server logs follow the same content-free rule. Automatic crash upload is disabled; any explicit diagnostic export is previewed and scanned and excludes queue/Keychain material.
- Sign and notarize Apple Silicon installer and update artifacts with Apple Developer ID. Embed a pinned Abisso release-manifest public key separately from platform signing trust. The updater requires HTTPS, valid signed manifest, artifact digest, architecture, allowed version transition, minimum-supported version, and Apple signature/notarization verification; manual confirmation is allowed. Any failure keeps the current version untouched. Trust-key rotation uses a current trusted release and key overlap or dual signatures; network metadata alone cannot replace a trust root. Document compromised-key recovery and explicit signed emergency rollback, while rejecting ordinary downgrade. Build immutable artifacts and an SBOM; keep signing material in an MFA-protected managed secret/signing service.
- The N→N+1 development update quiesces observation/upload before migration and preserves installation/machine/source identity, Keychain access, consent/policy state, exclusions, pause/private state, encrypted queue, uncertain retry state, durably accepted capability snapshot, stream/sequence and gap state, and update trust. Migrate transactionally or copy-on-write. Dispatch nothing until migrated state and Keychain/queue validation pass. On failure retain the old signed version with compatible untouched state or enter no-transmission Error; never reset controls, regenerate keys, re-enroll, or silently discard records.

### Required architectural seams and implementation discretion

The primary end-to-end seam is **fixture invocation → the production local privacy function → encrypted queue → existing authenticated batch ingestion → durable disposition → existing worker/Live**. Exercise negative inputs through that seam wherever possible. Additional focused seams are browser-to-machine enrollment, machine self-service refresh/pause, Keychain/SQLite recovery, and signed update verification. Keep provider-specific logic behind future adapters; do not turn the fixture into an adapter framework.

The current implementation needs additive changes: a real browser identity adapter and internal subject mapping separate from synthetic login; workspace creation and machine enrollment/lifecycle authority; versioned policy history/compatibility and consent; collector runtime and local control protocol; fixture source registration and an explicitly environment-gated source contract; and server pause admission before dispositions. The current source schema's `synthetic_m0` restriction and exact current-policy equality are concrete M1 incompatibilities to extend. Preserve M0 canonical event equivalence, request replay order, event deduplication, checkpoint meaning, projector, and minimal Live path.

Library selection, package layout, SQL types/indexes, IPC message encoding, exact retry backoff, installer container format, and initial numeric queue limits remain implementation discretion subject to these contracts and tests. A native helper is triggered only by a measured Keychain, signing-continuity, or IPC limitation that cannot be met safely in the TypeScript runtime. That trigger requires a focused decision and fixture, not a speculative helper.

## Defining tracer

On a clean Apple Silicon Mac: inspect trust summary → install signed/notarized development collector → start per-user LaunchAgent → Clerk browser sign-in → explicitly create a workspace → initiate PKCE/state and loopback enrollment → confirm/name machine → store Abisso credentials and workspace key in Keychain → review local dry-run preview and consent → invoke a visibly synthetic fixture session → pass eligibility, exclusion, private/pause, allowlist, derivation, redaction, and limits → serialize deterministic canonical bytes → encrypt and enqueue → explicitly preview queued bytes → authenticate and upload → receive durable disposition/checkpoint → observe the existing minimal Live projection and synthetic label.

Alternate/negative tracer runs must cover offline queue/restart/drain; pause with retained versus discarded queue and admission race; private-next-session and sticky mid-session privacy including uncertain pre-barrier upload; exclusions before derivation; policy narrowing/broadening and unknown compatibility; Keychain denial; queue corruption; count/byte overflow and local stream sealing with capability recovery after an unaccepted declaration is lost; uncertain request replay then expired-wrapper recovery; terminal revocation; offline sign-out and uninstall as separate paths; and signed N→N+1 update with preserved state and tamper/downgrade rejection. No scenario may create private or prohibited data in the shared outbound queue, logs, server, or Live.

## Testing Decisions

Tests assert externally visible outcomes and durable boundaries rather than private helper calls: what is queued, previewed, transmitted, accepted, rejected, shown as a gap, or left untouched after failure. Reuse M0's batch-ingestion, request/event equivalence, source-checkpoint, worker, realtime, and Live fixtures as prior art. Use sanitized synthetic privacy-adversarial fixtures; never capture real customer content as tests. The highest-value test seam is the full tracer above, with focused fault injection at enrollment, Keychain, SQLite, policy reconciliation, transport, and update verification.

### Executable CI-safe completion gate

`pnpm test:m1:gate` must be checked in and executable locally and in GitHub Actions repository CI. It must include typecheck, dependency-direction enforcement, and the following behavior:

1. **Contracts and privacy:** exact M1 fixture source/profile/capabilities, canonical limits and unknown-field failure, prohibited/secret corpus scans of queue, requests, responses, logs, crash/diagnostic paths, and output artifacts; no Claude/Codex impersonation. At the production serialization/HTTP transport seam, assert exact equivalence among explicit preview, decrypted canonical bytes in the encrypted queue, and the outbound canonical event/body before TLS framing; do not substitute a mock serializer or claim packet capture can inspect HTTPS payload categories.
2. **Enrollment and authority:** Clerk-to-internal-user mapping, explicit workspace membership, PKCE/state/redirect/code expiry and one-use binding, code digest only, machine versus browser route matrix, user/workspace/source mismatch, lost/reinstalled/duplicate machine cases.
3. **Credential lifecycle:** short access expiry, refresh rotation, exact 30-second replay, different/late reuse family revocation, keyed-hash-only persistence, self-service pause/revoke, offline and terminal authorization behavior.
4. **Consent and policy:** no enqueue before consent; dry run never transmits; narrower policy queued-byte recheck/discard; broader policy preserves old consent but requires new consent for added categories; explicit server compatibility, revoked/unknown version denial, local-control precedence.
5. **Exclusion and derivation:** repository-root and relative-glob precedence, malformed/traversal/symlink/nested-repository/case/Unicode fixtures, exclusion before derivation, same-workspace determinism, cross-workspace inequality, domain separation, key rotation and missing-key fail-closed behavior, zero raw path transmission.
6. **Preview and controls:** deterministic queued-event bytes equal explicit preview and uploaded event; safe reason metadata separate; inspect reveals counts/state only; pause and private races, sticky privacy across restart, no private session queue row or shared shell, honest pre-barrier accepted-fact limit.
7. **Buffer and retry:** AES-GCM ciphertext/tamper/nonce/AAD, atomic crash recovery, Keychain denial, inspect/discard, preserved order, deterministic 30-simulated-minute checked-in load profile, separate count and byte overflow, protected uncertain in-flight records, content-free gap, corrupt-record isolation, stream sealing and stalled-old-checkpoint handling, identical request replay, expired-wrapper rewrap with unchanged events, terminal per-event dispositions. Force offline loss/overflow to remove an original unaccepted `capabilities.declared`; prove the new stream independently declares capabilities, waits for durable acceptance, then emits dependent session evidence. Also prove a still-applicable durably accepted snapshot may be reused, and same-batch declaration never activates a sibling.
8. **Release/architecture checks:** manifest signature/digest/version/architecture/minimum-version rejection with test keys and artifacts; safe-log scans; imports obey the module dependency direction—contracts and local privacy cannot depend on browser/backend/database, the collector cannot reach server storage or projectors, and ingestion cannot use browser authority as machine authority.

GitHub Actions is repository CI only. It is not GitHub product integration or GitHub Actions telemetry. CI passing does not prove Apple installation, Keychain scoping, Developer ID signing/notarization, LaunchAgent behavior, or update continuity.

### Mandatory clean Apple Silicon machine gate

On a clean Apple Silicon macOS user account, record evidence for trust-summary/install and Gatekeeper/notarization; unprivileged LaunchAgent and CLI/IPC; Clerk login and explicit workspace creation; loopback enrollment and machine naming; non-synchronizing Keychain item access before and after restart/update; consent and dry-run preview; fixture tracer through Live; pause/private/exclusion/inspect/preview/discard controls; and offline/restart continuity. Test sign-out independently: local secrets and workspace-bound state disappear, collection stops, remote revocation status is truthful, and the installed collector may remain inactive for later enrollment. Test uninstall independently: sign-out destruction occurs and LaunchAgent, CLI/binary, IPC socket/runtime directory, and installation artifacts are removed. Exercise a real signed/notarized N→N+1 development update that preserves queued/retry/privacy state. Verify tampered manifest, altered artifact, ordinary downgrade, and failed migration/key access all fail closed. Packet capture proves TLS use, the expected destination, and absence of plaintext prohibited or canonical payload material on the wire; it does not inspect HTTPS payload categories. The CI-safe production transport-seam test proves preview, decrypted queued bytes, and outbound canonical event/body equivalence. Record pass/fail evidence; no CI substitution is allowed.

Apple Developer signing/notarization credentials and access to a clean Apple Silicon Mac are external completion prerequisites whose availability is not yet verified. If unavailable, report the milestone as incomplete rather than weakening the exit criterion.

## Out of Scope

No Claude Code or Codex adapters, GitHub product integration or Actions telemetry, general Work Graph correlation, Needs Attention, cost/outcome reconciliation, production orchestration, remote Workstream gap projection, replay expansion, Linux/Windows support, or Kafka/Redis/graph database/microservices. Full team invitation administration is not required for the clean-machine M1 path. M1's reference load profile does not establish real-adapter buffer capacity; recalibrate with measured Claude Code/Codex traffic in M3. Sender-constrained machine credentials are deferred until threat evidence or design-partner requirements justify them.

## Further Notes and completion claim

The V0 security acceptance wording for private mid-session evidence should be read with the higher-level PRD's temporal boundary: switching to private prevents further session evidence and removes unsent local session payloads; it cannot retract an already accepted pre-switch backend fact. This clarification belongs in the brief and future alpha test wording, not a silent change to a frozen specification.

**“M1 Collector Trust Shell complete” proves** that a clean Apple Silicon development installation can enroll an Abisso-owned machine, obtain explicit local consent, keep private/excluded/prohibited evidence outside the shared queue, preserve approved canonical bytes in an encrypted bounded offline buffer, upload/retry them safely through the existing M0 ingestion/Live path, survive local failure and a signed development update without losing privacy state, and pass both the executable CI-safe and clean-machine gates.

**It does not prove** real Claude Code/Codex adapter correctness, production Alpha Ready, external performance at real adapter volume, GitHub outcomes, Work Graph correlation, Needs Attention, cost accuracy, remote gap projection, Linux/Windows support, or that a copied identical bearer refresh request can be distinguished during the accepted 30-second retry window.

# Machine enrollment (issue #22)

The collector CLI starts an ephemeral listener on `127.0.0.1`, generates a 256-bit PKCE verifier and state, and opens `/enroll` at the configured HTTPS origin. A signed-in browser user confirms their one active workspace, enters a bounded display name, and approves the fixed `telemetry:write machine:self` scope. The browser receives a five-minute one-use code and redirects it with state to the local listener. The collector verifies state and exchanges the code, verifier, redirect URI, and new installation ID with the backend over HTTPS. Browser cookies and cross-origin requests cannot call the exchange endpoint.

The database stores only the code SHA-256 digest and a keyed refresh digest. The exchange commits code consumption, machine registration, a 15-minute machine access token, a 90-day refresh credential, and an append-only registration audit record in one transaction. An active installation ID can register only once. The access token can call the machine's own status endpoint and ingestion; browser data routes reject it. Enrollment creates no consent, collection configuration, or source; later M1 work must establish those before ingestion is admitted. The refresh credential is issued here, while rotation remains the subsequent lifecycle slice.

The CLI stores the refresh credential and machine identity in a non-synchronizing, device-only macOS Keychain item through the Security framework. The short-lived access token stays in collector memory and is discarded when the enrollment command exits. The Swift helper receives the secret on stdin, so it does not appear in process arguments, configuration, shell history, browser pages, or LaunchAgent properties. The CLI prints only `enrolled` or `enrollment_failed`.

Build the dedicated Keychain helper with `pnpm collector:keychain:build`, then run `pnpm collector:cli enroll https://<Abisso origin>` after configuring Clerk browser sign-in and `MACHINE_REFRESH_HASH_KEY` (a random server secret of at least 32 characters). A missing hash key disables exchanges. The API must be served through HTTPS for collector enrollment. The signed collector package must include the helper executable. Clean-Mac signing and Keychain persistence are verified in the M1 device gate (#42); CI uses an injected Keychain adapter and tests the browser, loopback, and backend exchange.

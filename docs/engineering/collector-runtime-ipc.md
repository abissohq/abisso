# M1-03 collector runtime and local IPC

The collector daemon runs as the current user. Start it with `pnpm collector:daemon` and query it with `pnpm collector:cli status`. This slice only reports `inactive`, `unenrolled`, and `stopped`; enrollment and other local controls belong to later M1 tickets. No provider observation, credentials, keys, or network upload occur here.

The default socket is `~/Library/Application Support/Abisso/runtime/collector.sock`. The daemon creates missing directories beneath the user's home with mode `0700`, verifies their owner, type, and safe modes, and rejects symlinks. It creates `daemon.lock` with mode `0600` and changes the socket to mode `0600` before it reports ready. The CLI verifies the directory and socket owner/type/modes before connecting. `--runtime-dir /absolute/path` is available for isolated development and tests; its parent must be owned by the current user and not group or world writable. A second daemon cannot replace a live owner's lock. After an unclean exit, the next start recovers a lock whose PID no longer exists; ambiguous or unsafe lock state fails closed.

IPC version 1 accepts only one JSON line containing exactly `{"version":1,"command":"status"}`. The CLI half-closes its write side after sending; the daemon decides the request after that end-of-input, so later chunks cannot turn one request into two. It has a 1024 byte request limit and a three second deadline from connection acceptance. The response is a fixed status or an enumerated error. Unknown fields and commands are rejected without echoing input. The CLI rejects unsupported versions. Neither side sends credential or key fields.

Node 24 does not expose a reliable peer UID API for Unix sockets on macOS. This slice therefore relies on the user-owned `0700` directory and `0600` socket as its cross-user boundary. A clean Mac validation of these runtime assumptions remains in issue #42. The process requires no root, Full Disk Access, or Accessibility permission.

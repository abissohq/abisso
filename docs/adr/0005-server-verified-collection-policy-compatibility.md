# Server verifies collection-policy compatibility across versions

M1 accepts queued canonical records under their original consented policy version only when the server holds an explicit, versioned relation proving that policy is narrower than or equal to the current effective policy. Version order alone proves nothing. A broader server policy therefore does not force re-consent for previously permitted categories, while newly permitted categories remain disabled until local consent. A revoked, defective, newly disallowed, or unknown policy version fails closed with a safe reason and local queue reconciliation; neither the collector nor ingestion rewrites an event or substitutes its policy version. This preserves immutable event identity and prevents server policy from silently broadening local collection.

# Idempotent machine refresh rotation has a 30-second retry window

M1 rotates Abisso-owned machine refresh credentials on use. Every refresh secret must have at least 256 bits of cryptographic randomness or equivalent cryptographic unpredictability. A lost response must not force a healthy collector to re-enroll, but storing a plaintext successor for replay would expand secret exposure. For an exact retry within 30 seconds of successful rotation, the server produces the same 256-bit cryptographically pseudorandom successor through a domain-separated, versioned cryptographic PRF/KDF keyed by server secret material and bound to the presented predecessor credential, installation, credential generation, rotation request ID, and request digest. An ordinary hash digest is not used directly as the credential. The server stores only keyed credential hashes and the minimum non-secret rotation metadata; the predecessor hash is retained for this exact retry only during that window. A different request, digest, or installation, or any reuse after the window, revokes the credential family.

An attacker who copies the complete bearer request is indistinguishable from the collector during the retry window. This is an explicit M1 residual risk. Evidence of credential theft or a design-partner requirement for stronger device binding triggers a decision on sender-constrained credentials such as DPoP. Browser identity remains separate from machine authority.

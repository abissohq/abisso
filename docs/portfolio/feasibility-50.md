## Privacy blocker

The [non-interactive interface documentation](https://learn.chatgpt.com/docs/non-interactive-mode) specifies a mixed JSONL event stream: lifecycle markers coexist with content-bearing items. The same page describes `--ephemeral` as preventing session rollout persistence; it does not establish a metadata-only output boundary. A final-answer schema controls model output, not which event families the stream emits.

The repository's [Codex mapping](../architecture/04-canonical-telemetry.md#21-codex-adapter-mapping) prohibits message, reasoning and tool-argument inputs. The approved ticket also requires prohibited bodies never to become observation objects or persisted/logged artifacts. [Local privacy enforcement](../architecture/06-security-privacy-threat-model.md#14-local-privacy-enforcement-pipeline) remains fail-closed.

A conventional whole-line JSON decoder followed by field removal would materialize prohibited values before filtering. Suppressing rollout files or promising a harmless final answer does not prove that acquisition is safe. The existing baseline contains no verified bounded extractor that skips those values before observation-object construction, nor a proved provider-side metadata-only feed for this CLI build. Consequently the required acquisition proof was not available at the point where live input would begin.

This does **not** prove that a bounded streaming extractor cannot work. The approved plan allows transient framing that does not build content-bearing drafts. Such an extractor needs an explicit, tested boundary; substituting an unverified filter during a live run would assume the condition the gate is meant to prove. No broader provider integration or relaxation of the production privacy requirement was attempted.
